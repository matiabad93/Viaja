## One-time setup (keep credentials out of source code and chat)

1. In Supabase Dashboard → Authentication → Users, provision **two separate confirmed test users** with email/password. Their email local parts **must start with `viaja-e2e-`**; for example, `viaja-e2e-a@your-controlled-test-domain.example` and `viaja-e2e-b@your-controlled-test-domain.example`. The addresses must be under your control. Do **not** repurpose actual user accounts. If email confirmation is required, finish it for both accounts.
2. In GitHub repository Settings → Environments → `production` → Environment secrets, add these five secrets (never in a PR, issue, source file, or chat):
   - `VIAJA_E2E_PUBLISHABLE_KEY`: **Supabase publishable** (not secret/service-role) API key for viaja-production
   - `VIAJA_E2E_USER_A_EMAIL`, `VIAJA_E2E_USER_A_PASSWORD`
   - `VIAJA_E2E_USER_B_EMAIL`, `VIAJA_E2E_USER_B_PASSWORD`
3. GitHub Actions → **Viaja - live two-account private PDF security E2E** → Run workflow on `main`. This is **workflow_dispatch only**; it never runs automatically during deployment.
4. Inspect the logs for `PASS` assertions and the final `PASS two-account PDF production E2E`. If it fails, locate the first failed check. Avoid posting raw response bodies; they might contain sensitive details.
5. After testing, confirm the synthetic reservation and its Storage object were removed. If an interrupted test prints a cleanup warning, inspect only the dedicated account's own fixture.

## Coverage

- Independently authenticate two existing test accounts using Supabase Auth.
- Owner creates one PDF metadata record under RLS/quota; other account cannot list it.
- Other account cannot invoke Cloudflare's document upload endpoint for that record; owner can.
- Owner signs a **120-second** private URL and downloads exactly the generated bytes.
- Other account cannot create a signed URL or use the authenticated Storage download endpoint.
- Other account cannot delete the Storage object or edit/delete the metadata; owner still has access.
- Owner removes the object then the metadata; record no longer exists.
- Cleanup in `finally` when any test fails after registration.

No Gemini calls, real reservations, payment transactions, or administrative API keys. There is at most one synthetic file. Each successful metadata registration consumes one daily document quota event even if the file is later deleted.

**Important security model:** a signed URL is a *bearer link*. Anyone possessing the URL may open it before expiration; the test verifies that another account cannot **mint** the URL, not that a leaked URL would be bound to its creator's session. Do not share signed URLs. Supabase notes that CDN caches can affect immediate revocation after deletion.
